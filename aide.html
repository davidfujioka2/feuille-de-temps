Field App Setup: Superintendent iPad App

Architecture and requirements summary for continuing development in a

new session.

Status: design agreed, ready for prototype

1. Overview

The app is an HTML web app hosted on GitHub Pages and installed on the

superintendent's iPad as a Progressive Web App (PWA). After one initial

load with internet, it runs fully offline from the copy stored on the

iPad. All of his working data (lists, favorites, drafts, signed reports)

lives on the iPad. Documents are exchanged manually through a shared

OneDrive folder that syncs with the office.

2. Key decisions

  • Offline first. No SharePoint or Microsoft Graph API integration.

The app never waits on the network.

  • PWA, not native. Not a native app. Accepted trade-off: the app

cannot write into the OneDrive folder automatically; transfers are

manual through the Share sheet and file picker.

  • GitHub for code only. Data is not stored on GitHub. GitHub hosts

the code only.

  • He owns his lists. The office provides the base setup once. After

that, the superintendent maintains his own lists; the office does not

edit them.

  • Office controls documents. The only shared, office-managed content

is the document folder in OneDrive.

3. Installation on the iPad

  1. Open the GitHub Pages URL in Safari while connected to the internet.
  1. The service worker caches all app files on the iPad.
  1. Tap Share > Add to Home Screen.
  1. Always launch from the Home Screen icon, not a Safari tab. Home

Screen apps are exempt from Safari's automatic data clearing, and

their storage is separate from normal browsing.

Note: a PWA runs on Safari's engine but shows no browser interface.

Opening a local HTML file from the Files app does not work (JavaScript

does not run in the preview), so the PWA method is required.

4. Lists, favorites and activities

  • First-run seeding. On first launch the app loads the bundled base

setup (contractors, activities, favorites). Later app updates never

overwrite his changes.

  • Instant saving. Adding activities, reordering favorites and

marking items inactive save instantly on the device, with no Save

button needed.

  • Active / inactive. Items are marked inactive, never deleted, so

older reports still display correctly. Inactive items are hidden from

pick lists.

  • Hidden IDs. Every list item has a hidden unique ID so renaming an

item does not break links in old reports.

  • Future additions. Build in a way to merge new default items into

his lists later without touching his edits.

5. Report workflow

Stage 1: Draft

  • Save Progress button stores the report on the iPad; auto-save every

few seconds as a safety net.

  • A drafts list lets him reopen and continue any report.
  • Draft printouts carry a DRAFT watermark.

Stage 2: Sign and approve

  • Approve opens a signature pad (finger or Apple Pencil).
  • Signature is stamped with his name, date and time.
  • The final PDF is generated on the iPad, offline.

Stage 3: Final (locked)

  • Status becomes Approved; editing is disabled and the report is

view-only.

  • Send options: Share > Save to Files > OneDrive folder, or Share >

Mail (queued in Outbox until signal).

  • Corrections create a new revision (Rev 1, Rev 2) instead of unlocking

the original, preserving an audit trail.

  • Optional: stamp a unique fingerprint (hash code) on the PDF so later

tampering can be detected.

6. Documents and sketches

  • The office maintains a shared OneDrive folder of documents (drawings,

specs, photos). This is a manual upload and download process.

  • He taps Add Document; the iPad file picker opens, showing OneDrive.

The app stores its own copy so it stays available offline.

  • Documents can be attached to reports or used as backgrounds for

sketches.

  • The app does not auto-refresh documents. If the office updates a file,

he re-adds it. Use revision numbers in file names, e.g.

A-101_Rev3.pdf.

  • The app should show stored documents and let him remove old ones to

manage space.

7. OneDrive requirements

  • In the OneDrive app, tap the three dots next to the shared folder and

choose Make Available Offline. Included with work/school accounts;

personal accounts need Microsoft 365.

  • Open the OneDrive app briefly on Wi-Fi before going to the field so it

pulls the latest files. iPadOS limits background syncing.

  • A cloud icon next to a file means it is not downloaded; no icon or a

checkmark means it is available offline.

Suggested folder structure:

Field App/

Documents/ (office-managed: drawings, specs, references)

Reports/ (approved PDFs he saves)

Sketches/ (exported sketches)

Backups/ (his app backup files)

8. Backup and restore

Because his data lives only on the iPad, losing or resetting the iPad,

or deleting the Home Screen icon, would erase it.

  • Export Backup button: saves one file with all lists, favorites and

reports to OneDrive/Backups.

  • Import Backup button: restores from that file. Also used to move his

setup to a new iPad.

  • Show a Last backed up date in the app as a reminder.

9. Known limitations

  • First launch requires internet.
  • The PWA cannot read or write the OneDrive folder automatically; every

transfer goes through the file picker or Share sheet.

  • No background activity; the app works only while open.
  • Only documents already imported into the app open offline.
  • Large photo and drawing sets use iPad storage; compress photos.
  • Once a PDF leaves the iPad, others could edit it with PDF software;

the fingerprint only detects changes.
